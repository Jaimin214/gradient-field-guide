Eight levels, in order

Learning path

Each level builds on the one before. Tick the checkpoint only when you can do it without notes; your ticks stay in this browser. Budget is a rough guide for 8–10 hours a week.

  1. L0~3 weeks

    Math and Python you actually need

    Vectors and matrices are how models store knowledge; derivatives are how they learn; probability is how they express uncertainty. You don't need proofs, you need intuition and NumPy fluency.

    vectors · dot productmatrix multiplygradients · chain ruleprobability · Bayesmean · varianceNumPy broadcasting
    • 3Blue1Brown: Essence of Linear Algebra video
    • Mathematics for Machine Learning free book
    • Khan Academy: Statistics & Probability course
    My notes
  2. L1~4 weeks

    Classical machine learning

    The vocabulary every AI conversation assumes: training vs. test data, overfitting, loss functions, metrics. Most real-world tabular problems are still solved here, not with LLMs.

    supervised / unsupervisedbias–variancecross-validationprecision · recall · F1decision trees · XGBoostk-means · PCA
    • Andrew Ng: Machine Learning Specialization course
    • scikit-learn User Guide docs
    • Kaggle Learn hands-on
    My notes
  3. L2~5 weeks

    Neural networks and deep learning

    Build backpropagation by hand once, then let PyTorch do it. Understanding why training diverges or stalls is what separates engineers from API callers.

    backpropSGD · Adamactivationsbatch norm · dropoutCNNsPyTorch autogradGPU basics
    • Karpathy: Neural Networks, Zero to Hero video + code
    • fast.ai: Practical Deep Learning course
    • Dive into Deep Learning free book
    • PyTorch Tutorials docs
    My notes
  4. L3~4 weeks

    Tokens, embeddings and attention

    The transformer is the engine inside every modern LLM. Once you've written self-attention yourself, papers and release notes stop being magic.

    tokenization (BPE)embeddingsself-attention · Q/K/Vmulti-headpositional encoding · RoPEdecoder-only GPT
    • Attention Is All You Need paper, 2017
    • Jay Alammar: The Illustrated Transformer article
    • Karpathy: Let's build GPT from scratch video
    • 3Blue1Brown: Neural Networks (transformer chapters) video
    My notes
  5. L4~4 weeks

    How LLMs are trained, served and run locally

    Pretraining gives knowledge; fine-tuning and RLHF give behavior. On the serving side, quantization and the KV cache decide whether a model fits on your GPU. Rule of thumb: a 4-bit GGUF needs about 0.6 GB of memory per billion parameters, plus room for context.

    pretraining · scaling lawsSFT · RLHF · DPOsampling · temperaturecontext windowKV cachequantization (Q4, GGUF)LoRAprompting
    • Hugging Face LLM Course course
    • Karpathy: Intro to Large Language Models video
    • Scaling Laws for Neural Language Models paper
    • Anthropic prompt engineering guide docs
    • Ollama and llama.cpp local runtimes
    My notes
  6. L5~4 weeks

    Building LLM applications

    Real products combine a model with your data (RAG), structured outputs, tool calls and, most importantly, evaluations. Without an eval set you can't tell whether a change helped.

    embeddings · vector searchchunking · rerankingRAGtool use · JSON schemaevals · LLM-as-judgelatency & costprompt caching
    • Anthropic Cookbook code recipes
    • Hamel Husain: Your AI product needs evals article
    • sqlite-vec vector search in SQLite
    My notes
  7. L6~4 weeks

    Agents, protocols and guardrails

    An agent is a model in a loop that chooses tools until a goal is met. MCP standardizes how tools plug in; A2A how agents talk to each other. The hard part is containment: least-privilege tools, sandboxes, approvals and defenses against prompt injection.

    agent loopworkflows vs. agentsMCP serversA2Aorchestrator + sub-agentsprompt injectionsandboxing · approvalscomputer use
    • Anthropic: Building effective agents article
    • Model Context Protocol docs spec + SDKs
    • Agent2Agent protocol spec
    • OWASP Top 10 for LLM Applications security
    • Claude Code docs agentic coding

Learn by poking at it

Playground

Two fixed toy mechanisms plus a third demo that changes with every refresh, tied to whatever is in the news. None is a trained model: the gradient descent demo optimizes a real function, and the attention demo runs the real Q·K softmax math on embeddings generated from a word hash rather than learned weights. Enough to build intuition for L0 and L3.

Gradient descent on a double well

f(x) = x⁴⁄4 − x². Click the curve to place the ball, or drag the start slider, then step through gradient descent. Too high a learning rate overshoots the minimum; starting on the wrong side finds the other one.

Self-attention weights

Type a short sentence. Each word becomes an 8-dimensional vector from a deterministic hash, and the grid shows softmax(QKᵀ/√d) — the formula from Attention Is All You Need, just without training. Darker cells mean a word attends more to that column.

New this refresh · 2026-09-26 · connects to L6

Prompt-injection filter toy

Pick a fake "document" an assistant might read, then flip the filter to see a toy pattern-matcher catch injected instructions before they reach the model — the same trick behind this week's viral Snickers HUNGR.AI campaign and real indirect-injection attacks. This is simplified keyword matching, not a real defense: a genuine filter needs far more than a few regexes, and cleverly worded text can still slip past this version.

        Plain-English definitions
        
          Glossary
          
        
          The vocabulary from the levels above. Each term links to the level that teaches it.
          
      
          
      
      
          
        
          Gradient descentL0
          Repeatedly nudging parameters in the direction that lowers the loss.
          
        
          Loss functionL1
          A single number saying how wrong the model currently is; training tries to shrink it.
          
        
          OverfittingL1
          Memorising the training data so well that new data is handled badly.
          
        
          Cross-validationL1
          Rotating which slice of data is held out, to estimate how a model will do on unseen data.
          
        
          BackpropagationL2
          Applying the chain rule backwards through a network to get every parameter's gradient.
          
        
          Epoch / batchL2
          One full pass over the data / the small chunk processed per update.
          
        
          TokenL3
          A chunk of text (word piece) that a language model reads and writes.
          
        
          EmbeddingL3
          A vector of numbers representing a token or document so similar meanings sit close together.
          
        
          Self-attentionL3
          Each token computes weights over other tokens to decide what to draw information from.
          
        
          TransformerL3
          The attention-based architecture behind nearly all modern LLMs.
          
        
          Context windowL4
          The maximum number of tokens a model can consider at once.
          
        
          TemperatureL4
          A sampling knob: low is predictable, high is more varied.
          
        
          Fine-tuning (SFT)L4
          Further training a pretrained model on examples of the behaviour you want.
          
        
          RLHF / DPOL4
          Training a model to prefer answers humans rated higher.
          
        
          LoRAL4
          Fine-tuning a small set of added weights instead of the whole model.
          
        
          QuantizationL4
          Storing weights in fewer bits (e.g. 4-bit) so a model fits in less memory.
          
        
          KV cacheL4
          Saved attention keys/values so each new token doesn't recompute the past.
          
        
          RAGL5
          Retrieval-augmented generation: fetch relevant documents, then have the model answer from them.
          
        
          Vector searchL5
          Finding the stored embeddings nearest to a query embedding.
          
        
          Eval setL5
          A fixed set of test questions with known good answers, used to check whether a change helped.
          
        
          LLM-as-judgeL5
          Using a model to grade another model's outputs against a rubric.
          
        
          Tool useL6
          The model emits a structured request (e.g. JSON) that your code runs, then returns the result.
          
        
          AgentL6
          A model in a loop that chooses tools and actions until a goal is met.
          
        
          MCPL6
          Model Context Protocol: an open standard for plugging tools and data into AI apps.
          
        
          Prompt injectionL6
          Malicious text in the input or a tool result that tries to hijack the model's instructions.
          
        
          DistillationL7
          Training a small model to imitate a larger one.
          
        
          Mixture of expertsL7
          A model where each token is routed to only a few specialist sub-networks.
          
        
          InterpretabilityL7
          Research into what is happening inside a model and why.
          
      
          
      
          No matching terms.
